# LIBS 煤炭发热量预测 — 数据特点与训练策略

## 一、数据组织方式

- **光谱文件**：每个 CSV 为一次 LIBS 打谱结果，包含 7305 维（波长 + 强度）特征。
- **批次划分**：同一矿场同一日期采集的多条光谱归为一个**批次**（一个日期文件夹），同批次内的 N 条光谱共享同一个发热量 Q 标签和辅助指标（全水分、灰分、氢、硫等）。
- **标签来源**：各矿场的标签 Excel 文件，每一行 = 一个批次，按 `(矿场名, 日期)` 匹配到光谱批次。

## 二、数据集规模

| 维度 | 数值 |
|:----|:----:|
| 光谱样本总数（训练集） | 944 条 |
| 有效标签数（批次总数） | 70 个 |
| 特征维度 | 7305 |
| 测试集光谱数 | 358 条 |
| 测试集批次数 | 26 个 |

**核心矛盾**：944 条光谱仅对应 70 个唯一标签——每条标签平均被约 13.5 条冗余光谱共享。**高维小样本 + 多对一弱对应关系**。

## 三、特征工程

原始光谱每条为 7305 维（波长 + 强度），经过三层特征提取后拼接为一个约 73 维的最终特征矩阵，再送入 Ridge 模型。

### 3.1 全光谱 PCA 降维

- 先对每条光谱做归一化（除以总强度，消除激光能量波动）。
- 再进行标准化 → PCA 降维到 `min(30, 批次数-1)` 维。
- PCA 保留全光谱的整体形态信息（主成分反映光谱的主要变化方向）。

### 3.2 手工特征提取

从每条光谱的原始数据中提取 43 维手工特征，分为三类：

**统计特征（17 维）**：均值、标准差、最大值、log1p(总能量)、归一化均值/标准差、偏度、峰度、信息熵、10%/25%/75%/90% 分位数、一阶导数标准差/均值绝对值、二阶导数标准差。

**谱线积分（22 维 = 11 绝对 + 11 相对）**：
针对 11 个关键元素，提取其特征波长窗口内的强度积分（绝对强度）+ 除以总强度（相对强度）：

| 元素 | 中心波长 (nm) | 半窗口 (nm) | 物理意义 |
|:---|:------------:|:----------:|:--------|
| C | 247.86 | 2.0 | 最主要发热元素 |
| H | 656.30 | 3.0 | 发热量贡献仅次于碳 |
| O | 777.20 | 3.0 | 与含水量相关 |
| N | 742.40 | 2.0 | - |
| Ca | 422.70 | 2.0 | 灰分指示 |
| Ca2 | 393.40 | 2.0 | 钙的第二条谱线 |
| Mg | 285.20 | 2.0 | - |
| Al | 308.20 | 2.0 | - |
| Si | 288.20 | 2.0 | - |
| Fe | 438.40 | 3.0 | - |
| Na | 589.00 | 1.5 | - |

**物理比值（4 维）**：基于谱线积分值计算的先验知识特征：
- 可燃元素总和 / 灰分元素总和（发热量代理指标）
- H / 灰分
- C / 灰分
- H / C

### 3.3 特征矩阵拼接

```
最终特征 = [PCA 主成分 (~30 维)] + [手工特征 (43 维)]
         = 约 73 维
```

三层互补：PCA 看全貌，谱线积分抓关键元素，物理比值引入先验知识。

## 五、训练策略

### 5.1 分矿场独立训练

每个矿场训练自己的模型，不混入其他矿场数据。原因是不同矿的煤质差异较大，发热量范围不同（中马矿 2752~3848，赵固一矿 4708~6143），合并训练 Ridge 难以拟合多分布数据。

### 5.2 GroupKFold 按批次分割 CV

- 以**批次**为 group 单位进行交叉验证分割。
- 同一批次的多条光谱要么全在训练集、要么全在验证集，不会两端都出现。**防止数据泄露**。
- 批次数 ≤ 10 的矿场 → LeaveOneGroupOut（留一批次做验证）
- 批次数 > 10 的矿场 → GroupKFold(5折)

### 5.3 两阶段 Stacking

**Stage 1：光谱 → 辅助指标（全水分/灰分/氢/硫）**
- 先让 Ridge 模型从光谱预测煤的成分指标。
- 这些辅助指标与发热量有物理相关性，且比发热量更稳定。

**Stage 2：[光谱特征 + Stage1 预测的辅助指标] → 发热量 Q**
- 拼接光谱特征和 Stage1 预测值，送入第二个 Ridge 模型预测最终发热量。
- 相当于引入物理中间变量，缓解直接从 7305 维→1 个标签的过拟合。

**OOF（Out-of-Fold）预测**：
- Stage 1 不做全量预测，而是利用 GroupKFold 在每折中：用训练部分训模型 → 预测验证部分。
- 所有折跑完后，每条光谱的辅助指标预测值都是在"自己没参与训练"的情况下生成的。
- 用这些 OOF 值送进 Stage 2，避免数据泄露。

### 5.4 批次聚合

同一批次的多条光谱各得到一个 Q 预测值后，取**中位数**作为该批次的最终预测结果。中位数比均值对异常光谱更鲁棒。

### 5.5 均值收缩（Mean Shrinkage）

小批次矿场（≤10 批，即中马矿、赵固一矿、赵固二矿）的预测值向该矿场的平均发热量收缩：

```
pred = w × 模型预测 + (1-w) × 矿场均值
```

w 通过 OOF 验证集上网格搜索（0.0~1.0，步长 0.05）确定。当模型预测不可靠时，退回到"大概就是这些煤的平均值"。

## 六、关键设计思路总结

| 问题 | 应对 |
|:----|:----|
| 同一批次多条光谱标签完全相同 | GroupKFold 按批次分割 |
| 高维小样本（7305 维 vs 70 标签） | RidgeCV 强正则化 + 两阶段 stacking |
| 直接预测发热量过拟合 | 先预测辅助指标引入物理先验 |
| 小批次矿场过拟合严重 | 均值收缩向矿场均值靠拢 |
| 同批次光谱预测值波动 | 取中位数聚合 |

## 七、评估指标与模型选择经验（2026-07-11 更新）

### 7.1 全局 CV-RMSE：按批次数加权平均

原使用各矿场 Stage2 CV-RMSE 的简单平均，经验证该指标与线上分数不协同（3 组实验中 2 组方向相反）。

改为按批次数加权平均后（批次数多的矿场其 CV 估计更可靠，权重更高），同样的 3 组实验本地 CV-RMSE 与线上分数变化方向实现全协同。

加权方式验证结果：
- 简单平均：2/3 方向不匹配 ❌
- 按批次数加权：3/3 匹配 ✅
- 按光谱数加权：3/3 匹配 ✅
- 仅大批次(>10 批)：3/3 匹配 ✅

详见 `EXPERIMENT_LOG.md` 实验 #4 及 `src/weight_analysis.py`（已归档，结果已纳入项目）。

### 7.2 RidgeCV alpha 候选集不宜过密

在 ≤30 批的训练集上，为 RidgeCV 添加更多 alpha 候选值（如 0.1/0.5 或 1/3/10/30 等比序列）会导致 alpha 选择本身过拟合到 CV 折的噪声上，即使是在嵌套 CV 框架中。

推荐使用原始网格 `[1, 10, 50, 100, 500, 1000, 5000, 10000]`，跨度大、候选少，RidgeCV 内部的 alpha 选择过拟合风险最低。

### 7.3 KEY_LINES 窗口宽度对 PCA+Ridge 架构不敏感

实测各元素谱线峰值位置和 FWHM 后修正了 KEY_LINES 的中心波长和半窗口，但线上分数反而略变差。原因：全光谱 PCA 已经包含了谱线形状信息，手工特征的窗口宽度变化信息与 PCA 冗余。如需精细调整窗口，可使用 `src/window_search.py` 工具辅助探索。

### 7.4 工具可用

- `src/window_search.py`：窗口宽度自动搜索（支持全局因子扫描和逐元素扫描）
- `config.py` 中 `WINDOW_CANDIDATES` 和 `WINDOW_MULTIPLIER` 控制搜索参数
- `src/experiment_tracker.py`：实验日志自动记录到 `output/experiment_log.csv`
